# Web Demo Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local three-column React web app (groups, chat with citations, pipeline trace) over the existing FastAPI RAG API, plus the three read endpoints and the `trace` block it needs.

**Architecture:** Backend gains `GET /groups`, `GET /groups/{id}/members`, `GET /groups/{id}/messages/{mid}/context`, and a `trace` on `/ask` built by a pure function from the chain state (retrieval split into `hits` then `candidates`). Frontend is a Vite SPA in `web/`; the Vite proxy injects `X-API-Key` so the key never reaches the browser.

**Tech Stack:** FastAPI, SQLAlchemy, LangChain LCEL (existing); React 18, Vite 5, TypeScript strict, CSS Modules, Vitest, `@fontsource/source-serif-4`, `@fontsource/ibm-plex-sans`, `@fontsource/ibm-plex-mono`.

**Spec:** `docs/superpowers/specs/2026-10-26-web-demo-design.md`

## Global Constraints

- No commits or pushes (CLAUDE.md). Every "Commit" step is replaced by "Checkpoint: run the task's tests and lint".
- File edits through the Edit/Write tools, not shell (CLAUDE.md).
- Python: ruff + black, line length 100; tests use fakes only (no network, no GPU).
- Visual: Ledger tokens exactly as spec §2; radius 2-4px; no gradients, pill shapes, emoji, em dashes in UI copy, invented numbers, marketing hero.
- Motion 120-180ms opacity/translate only; none under `prefers-reduced-motion`.
- Rerank scores are raw logits; label "rerank logit", 2 decimals.
- The API key is never in `web/src` or the bundle; only `vite.config.ts` reads it from `../.env`.
- React renders chat text as text; no `dangerouslySetInnerHTML`.
- `query_logs` unchanged: no trace or chat text added to it.

## Review Focus

1. API not running: the proxy returns a non-JSON 502/504; UI must say "API not reachable at 127.0.0.1:8000. Run make run." instead of a JSON parse error (Task 4 test).
2. Re-importing the same export: `new_messages: 0` is a success, shown as "No new messages; already imported", not an error (Task 5 manual check, Task 1 test asserts 200 + 0).
3. Answer text with `[7]` when only 3 sources exist, or no markers: out-of-range markers render as plain text, never a broken link (Task 4 test).
4. Context at the chat edges: target is the first or last message; window returns fewer messages, no error (Task 2 test).
5. Very long unbroken Hinglish words or URLs in messages: wrap (`overflow-wrap: anywhere`), no horizontal scroll at 400px (Task 7 manual check).

**Files:**

**Interfaces:**
- Produces schemas: `TraceQuery{text: str, vector_hits: int}`, `TraceRetrieval{queries: list[TraceQuery], fts_query: str, fts_hits: int, merged: int}`, `TraceChunk{chunk_id: int, start_ts: str, end_ts: str, participants: str, score: float | None, preview: str, cited: bool}`, `Trace{rewrite: Rewrite, retrieval: TraceRetrieval, reranked: list[TraceChunk], best_score: float | None, min_relevance: float, gated: bool, rerank_enabled: bool, prompt_version: str, latency_ms: int = 0}`; `AskResponse.trace: Trace`.
- Produces: `build_trace(state: dict, *, cited_ids: set[int], gated: bool, min_relevance: float, rerank_enabled: bool, prompt_version: str, tz: str) -> dict` in `trace.py`. `state` has keys `rewrite`, `hits` (`{"vector": list[list[Document]], "fts": list[Document], "fts_query": str, "queries": list[str]}`), `candidates`, `top`.
